\section{Execution and Resource Costs}\label{sec:execution}
\subsection{Platforms and matched operators}
The primary server (fy) has four RTX~5090 graphics processing units
(GPUs). Four DGX Spark hosts (Spark1--Spark4) each provide a GB10 GPU and a
20-core Arm central processing unit (CPU); the host Spark-ebaf (ebaf for
short) supplies the Arm CPU measurements.
Python~3.12.3, NumPy~2.5.4, and CuPy~14.2.0 support the word-size backend;
Basic Linear Algebra Subprograms (BLAS) on the CPU use four threads. The large-field C++17 kernel is
single-threaded. The machines are shared and retain their existing
workloads. Independent sweeps use separate devices; each host's
long-stream extension runs sequentially.

The incremental operator computes $Y=V^\top B$ and $UY$, then adds
the retained product. Full recomputation forms $A'B$. Both pipelines
maintain $A'=A+UV^\top$ when the application retains $A$.
Table~\ref{tab:resource-counts} separates this common update from product
construction. These direct counts also distinguish the work model's
fresh bilinear products from fixed-right transforms, verification, and
state access. The theoretical model admits fast bilinear programs.

\subsection{Exact arithmetic and candidate interface}
The main backend uses $q=65521$ with canonical residues.
Double-precision floating-point (FP64) general matrix multiplication
(GEMM) evaluates each product, followed by conversion to signed 64-bit
integers and modular reduction. Every tested inner dimension $d\le4096$ satisfies
\[
 d(q-1)^2\le4096\cdot65520^2<2^{44}<2^{53}.
\]
All nonnegative integer products and partial sums are exactly
representable; subsequent additions are integral. This follows the
word-size-field approach of exact linear algebra~\cite{dumas2008fflas}.
The separate $q=2^{61}-1$ backend uses 128-bit products, reducing every
product and accumulated sum modulo $q$.

The NumPy/CuPy backends materialize a complete canonical 32-bit candidate,
copy it into a read-only host snapshot, and hash its bytes with the round
context before generating checks. The $q=2^{61}-1$ backend instead
delivers a separate immutable 64-bit matrix without a digest.
The received copy is checked using
operating-system randomness and unbiased rejection sampling. Rejection
leaves the reference unchanged and ends the sequence. The digest records
byte fixation; the program-class guarantee uses the execution contract
of Section~\ref{sec:heterogeneous}.
Retaining $A,B,C$ requires $3n^2$ field words. At $n=4096$ the candidate
alone occupies $64$\,MiB; the $r=8$ GPU run's maximum live-array
allocation is $1.75$\,GB, including benchmark reset snapshots.

\subsection{Structured analytical views}
Let $X,Y\in\F_q^{n\times d}$ contain $n$ records with $d$ features, with
$Y$ fixed. Maintain $A=XY^\top$ and $C=AB$. Replacing $b$ rows of $X$ with
difference $D\in\F_q^{b\times d}$ and selector $E\in\F_q^{n\times b}$ gives
\begin{equation}\label{eq:structured-update}
 \Delta A=E(DY^\top),\qquad \Delta C=E((DY^\top)B).
\end{equation}
Implementations use row gather/scatter. A factorized baseline caches
$H=Y^\top B$ and applies $E(DH)$, charging construction of $H$ and
its $dn$ retained field words. Setup-inclusive comparisons use each
method's actual initialization, including $XH$ where applicable.
The deterministic selector has zero linear escape, so this view measures
structured reuse. The randomized-report view below also instantiates
the nonuniform work guarantee.

Covertype contains $581,012$ records and $54$ integer features
\cite{covertype}. The row-replacement study excludes the class label
and maps features into $\F_{65521}$. Five disjoint source regions
provide initial tables, reference tables, and unrecycled replacement
streams, using seed identifiers $101,211,307,401,503$. Each trial uses
$n$ rows per initial table and $kb$ replacement rows. Methods share
inputs and rotate execution order across seed/repeat pairs.

\subsection{Measurement}
Matrix-engine latency starts with fresh-input transfer and ends after the
accepted state advances. It includes candidate copies, applicable hashing,
challenge generation, checks, and necessary device synchronization. Fixtures,
resets, and correctness oracles are recorded separately. The unchecked
ablation removes only checking from the same candidate interface.
Synchronized component diagnostics use separate runs and are not
substituted for end-to-end latency.

A complete update includes common maintenance, transfers, freezing,
enabled checking, and state advancement. Each matrix-engine round is
compared with a full product on the same backend; small products and
selected coordinates are independently checked with Python integers. A mismatch stops that run. Live device arrays,
reserved allocator memory, reset snapshots, and process-lifetime resident
set size (RSS) are distinguished. The randomized-report service validates typed-plan
admission, candidate fixation, reject-without-advance, and per-round
integer decoding; a post-stream integer reconstruction checks its complete
decoded output. Its verification model and statistical
noise are reported separately.
